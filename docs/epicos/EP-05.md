# EP-05 — Autenticação e Perfis de Acesso

Ver matriz completa de permissões em [../vocacional/rbac.md](../vocacional/rbac.md).

## US-01 — Usar o produto sem barreira de entrada

Como visitante, quero poder fazer o teste e usar o chat sem me cadastrar.

- **RF-08**: o sistema deve permitir o uso completo do teste vocacional e do
  chat livre sem autenticação.

## US-02 — Cadastrar-se para salvar o histórico

Como visitante, quero poder me cadastrar após o teste, para salvar meu
resultado e não perdê-lo.

- **RF-09**: o sistema deve oferecer cadastro (nome, e-mail, senha) ao final
  do teste.
- **RN-08**: ao se cadastrar, a sessão de teste anônima concluída deve ser
  vinculada à nova conta, para aparecer no histórico (EP-06).

## US-03 — Login administrativo

Como administrador ou orientador, quero fazer login para acessar o painel
administrativo.

- **RF-10**: o sistema deve autenticar administradores e orientadores via
  e-mail/senha, emitindo um token JWT em cookie httponly (a ser implementado
  no `apps/backend`, em NestJS).

## US-04 — Proteger rotas administrativas

Como sistema, quero restringir o acesso ao painel administrativo, para
proteger dados sensíveis (métricas, catálogo).

- **RN-09**: rotas administrativas só podem ser acessadas por sessões com
  perfil `orientador` ou `administrador`; o backend valida o perfil a cada
  requisição.
- **RN-10**: orientador tem acesso somente leitura — qualquer escrita
  (CRUD) deve ser negada com 403.

> Status de implementação: nenhum item deste épico está implementado no
> Chat-2026 — hoje não há models de usuário, autenticação nem
> proteção de rotas. É o próximo épico a priorizar depois do fluxo
> conversacional (EP-02/03/04), pois habilita EP-06, EP-07 e EP-08.
